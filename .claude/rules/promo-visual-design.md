# 販促キービジュアル制作ルール（ポップ・マキシマリズム様式）

日本のアプリ広告・キャンペーングラフィックで主流の「ポップ・マキシマリズム（盛りデザイン）」を、
標準レベルで再現するための制作ルール。担当: graphic-designer（様式の一次参照元）。
key-visual-producer / ui-designer / brand-guardian も販促ビジュアル関連作業時に参照する。

参考解析元: CHAT GAME キービジュアル（1080×1350 相当 / 4:5 縦型 / Web アプリ販促ポスター）

---

## 0. 様式の定義

- **一言で**: 高情報密度・高彩度・極太タイポ・装飾過多を「統制された賑やかさ」としてまとめる日本の販促様式
- **目的**: 3秒で「何のサービスか」「何が嬉しいか」「次に何をするか」を伝える
- **成立条件**: 盛っているのに読める。この両立が品質基準。「盛ったが読めない」は不合格、「読めるが寂しい」も不合格

### 密度と統制のバランス原則

| 統制手段 | 内容 |
|---------|------|
| 色の統制 | 使用色相は実質2系統 + アクセント1色に制限（後述） |
| 領域の統制 | 装飾は外周・隙間に配置。顔・文字・UIモック内部には重ねない |
| 階層の統制 | サイズジャンプ比 1:4 以上で「最初に読むもの」を強制する |
| モチーフの統制 | 装飾モチーフはプロダクトのテーマに紐づける（例: ゲーム×チャット → ピクセルカーソル・吹き出し・ハート） |

## 1. アートボードとレイアウト解剖（アナトミー）

### 標準アートボード

| 用途 | サイズ | 備考 |
|------|--------|------|
| SNSフィード / ポスター | 1080×1350（4:5） | 標準。参考解析元と同比率 |
| 正方形 | 1080×1080（1:1） | 要素を再レイアウトして作る（クロップ禁止） |
| OGP | 1200×630 | 横型に再レイアウト |
| ストーリー | 1080×1920（9:16） | 縦積みに再レイアウト |

異なるアスペクト比は**必ず再レイアウト**する。`object-fit: cover` によるクロップ量産は禁止（`.claude/rules/image-production.md` 準拠）。

### 9ゾーン構成（参考画像の解剖結果）

```
┌─────────────────────────────────────┐
│ [1]フックタグ         [3]カテゴリバッジ群  │
│ [2]メインキャッチ                        │
│    （最大・斜め）      [4]人物写真        │
│                      （ウインク+指差し）  │
│ [5]サブコピー（リボン帯）                 │
│ ┌───────────────────────────┐          │
│ │ [6]プロダクト証明（UIモック）  │[7]マスコット│
│ │  Step1 → Step2 の使い方デモ  │          │
│ └───────────────────────────┘          │
│ [8]ロゴロックアップ    [9]CTAクラスタ     │
│ [10]特徴3点（アイコン+短文）              │
└─────────────────────────────────────┘
```

| # | ゾーン | 内容 | 面積目安 |
|---|--------|------|---------|
| 1 | フックタグ | 短い前振りコピー（「ルールをコピペ」「すぐ遊べる」）を黄色の角度付きタグで | 3% |
| 2 | メインキャッチ | 最大の要素。体言止めの2フレーズ（「貼るだけで対戦相手」を2行に分割等。**句読点禁止**、下記）。-3〜-6° 回転 | 25-35% |
| 3 | カテゴリバッジ群 | 属性を英語ピルバッジで（WEB APP / NO INSTALL 等）。半透明白枠 | 3% |
| 4 | 人物写真 | 切り抜きモデル。大げさな表情 + 指差しでプロダクトへ視線誘導 | 25-35% |
| 5 | サブコピー | 仕組みの一文をグラデーションリボン帯で。階段状に2行 | 5% |
| 6 | プロダクト証明 | 実UIを模したブラウザ/スマホウィンドウ。使い方が読めるレベルで再現 | 30-40% |
| 7 | マスコット | UIウィンドウの縁にオーバーラップさせ奥行きを作る。吹き出し付き | 8% |
| 8 | ロゴロックアップ | 3D押し出しの英字ロゴ + 読みがなピル + タグライン枠 | 12% |
| 9 | CTAクラスタ | 黄色バースト（「今すぐためす！」）+ ボタン + カーソル | 8% |
| 10 | 特徴3点 | アイコン + 短文のゴーストピルを最下段に等間隔 | 4% |

面積合計が100%を超えるのは要素が重なり合うため（レイヤー構造前提）。

### レイヤースタック（z順・下から上）

```
L0 背景グラデーション（対角: ピンク→パープル）
L1 放射光線（サンバースト、左上または中央上から）
L2 大型装飾（ハーフトーン群・大きな稲妻・幾何学）
L3 人物写真（切り抜き）
L4 プロダクト証明（UIモック）
L5 マスコット（L4の縁にオーバーラップ）
L6 テキスト要素（キャッチ・リボン・バッジ・タグ）
L7 CTAクラスタ
L8 前面小型パーティクル（スパークル・カーソル。顔と文字には重ねない）
L9 グレインオーバーレイ（全体を統一する薄いノイズ）
```

### 視線誘導（Z字フロー）

```
①フックタグ+キャッチ（左上） → ②人物の顔（右上）
   → ③指差しに従ってUIモック（中央） → ④CTA（右下） → ⑤ロゴ（左下）
```

- 人物の視線・指差し・矢印・カーソルは必ず「次に見せたい要素」へ向ける
- CTAはZ字の終点（右下）に置く

## 2. カラーシステム

### 構成（60/30/10）

| 役割 | 比率 | 内容 |
|------|------|------|
| 主役グラデーション | 60% | 類似色相2色の対角グラデ（例: ピンク→パープル）。背景・キャッチ・リボンを同系で染める |
| 白 | 30% | 情報の地。UIモック・縁取り・バッジ枠・ロゴ面 |
| アクセント | 10% | 補色系1色（例: イエロー）。**行動を促す要素（フックタグ・CTA）専用** |

### プリミティブトークン（参考画像の実測近似値）

```css
:root {
  --pop-pink-400: #FF6FB5;
  --pop-pink-500: #FF3E8F;   /* キャッチA・リボン */
  --pop-magenta-600: #E81584;
  --pop-purple-400: #A78BFA;
  --pop-purple-500: #7C3AED; /* キャッチB・ユーザーバブル */
  --pop-purple-700: #5B21B6; /* 押し出し影 */
  --pop-yellow-400: #FFE93B; /* アクセント（CTA専用） */
  --pop-white: #FFFFFF;
  --pop-ink: #1F1235;        /* アクセント上の文字色 */
}
```

セマンティック層（`--kv-bg-from`, `--kv-catch-primary`, `--kv-accent-cta` 等）を挟んでから使う（`.claude/rules/design-system.md` のトークン3層構造準拠）。

### 配色ルール

- 背景は単色禁止。**対角線グラデーション + 放射光線 + ハーフトーン**の3層で奥行きを作る
- アクセント色をCTA以外（装飾・見出し）に使わない。アクセントの乱用 = CTAの死
- 人物写真のライティングは背景色相に寄せる（ピンク背景ならピンクのリムライト/色かぶり）。合成感の排除に最重要
- 白文字を背景に直置きしない。必ず縁取り・座布団（帯/バッジ）・シャドウのいずれかを敷く

## 3. タイポグラフィ

### キャッチコピーの句読点禁止

**キャッチ・フックタグ・タグライン等の見出し系テキストに句読点（、。）を使わない。**

- 「〜で、〜。」形の読点区切り + 体言止め句点はAI生成コピーの定型文法であり、
  見る人に「AIが作った」と伝わってしまう（2026-08-29 ユーザー指摘により禁止指定）
- リズム・区切りは句読点ではなく**改行・色替え・サイズ差・字間・タグ分割**で作る
  - Bad: 「貼るだけで、対戦相手。」
  - Good: 「貼るだけで」「対戦相手」を2行・2色に分割（句読点なしで同じリズムを作る）
- 本文・サブコピー・UIモック内の会話文は通常の文章なので句読点を使ってよい。
  禁止対象はあくまで見出し系（キャッチ・フックタグ・タグライン・バーストコピー）

### 書体 — プロの定番を真似る（オリジナル発明禁止）

**フォントは選ぶもので、作るものではない。** 日本の広告業界で実績のある定番書体
（モリサワ・フォントワークス等）を基準にし、その無償代替を採用する。
フォントワークスが Google Fonts に無償公開している書体（Dela Gothic One 等）は
「プロと同じ供給元」であり第一候補。

| 役割 | 広告業界の定番（商用） | 採用フォント（無償・Google Fonts） |
|------|----------------------|----------------------------------|
| **日本語の基準（キャッチ・本文とも）** | UD新ゴ / ヒラギノ角ゴ | **Noto Sans JP**（定番中の定番。キャッチは 900、本文は 400-700） |
| ポップ・キュート訴求のアクセント | スーラ U / じゅん501 | M PLUS Rounded 1c 900 / Mochiy Pop One（丸ゴ） |
| ディスプレイ書体（バースト・ロゴ等の限定用途） | ラグランパンチ | Dela Gothic One / Train One — キャッチ全体には使わない |
| 縁取り・立体が最初から設計された見出し | — | Train One（縁取り内蔵） / Rampart One（立体内蔵） |
| 英字ロゴ・バッジ | Futura Extra Bold / Helvetica Black | Montserrat 800-900 Italic / Titan One / Baloo 2 |

- キャッチは**書体自体が極太**のものを使う。普通のフォントを縁取りで太らせてキャッチと呼ばない
- **迷ったら Noto Sans JP 900。** 現行トレンドの事実上の標準であり、これを外す選定には
  明確な理由（ポップ訴求で丸ゴ等）を成果物に明記する。無名フォントの発掘で冒険しない
- **フォント選定前にトレンド確認を必須とする**: WebSearch 等で当年の日本語Webフォントの
  採用実績・トレンドを確認してから選定する（`platform-experts.md` の最新情報収集と同思想）。
  確認できない環境では Noto Sans JP 900 に落とす（最も安全な現行標準）
- 選定理由を成果物に1行で記す（例:「トレンド標準の Noto Sans JP 900 を採用」）
- 英字は**イタリック + letter-spacing** でスピード感を出す
- 細いウェイトはこの様式では使わない

### フォント読み込み確認（必須・省略不可）

**フォールバックフォントで組まれたKVは、レイアウトが正しくても不合格。**
縁取り・押し出しは極太フォントの字画太さを前提にした技法であり、細いシステムフォント
（IPAゴシック等）にそのまま乗せると文字が潰れて読めなくなる。

1. 使用する全フォント・**全ウェイト**を `@font-face` / Google Fonts で読み込む
   （静的読み込みの場合、使用する font-weight を全て列挙して読み込む。読み込んで
   いないウェイトを指定すると合成ボールド/丸めが起こり、環境によって品質が変わる）
2. スクリーンショット検証は**全テキストゾーンで行う**: キャッチ・ロゴ・リボン・
   バッジ・UIモック内・付箋・吹き出し・CTA・特徴の全て。**1ゾーンでも
   フォールバック落ち・合成ボールドがあれば不合格**。キャッチだけ確認して
   合格判定することを禁止する。ズームクロップで1ゾーンずつ目視確認する
3. プログラム確認する場合: `await document.fonts.ready` 後に
   `document.fonts.check('900 1em "Noto Sans JP"')` が true であること
4. フォント未読込のスクリーンショットを検証結果・成果物として提出しない
5. ヘッドレス/プロキシ環境では Google Fonts の取得が**エラー表示なしに**失敗することがある
   （カスタムCA等）。その場合は TTF をダウンロードしてシステムにインストール
   （`fc-cache -f` で反映）するかローカル `@font-face` で読み込み、必ず目視で書体を確認する

### 縁取り幅の比例則

縁取り・押し出しの太さは**字画の太さに比例**させる。上限の目安:

| 項目 | 上限 |
|------|------|
| 白縁（-webkit-text-stroke） | フォントサイズの 4-7%（900ウェイト時） |
| 押し出し（text-shadow累積） | フォントサイズの 8-12% |

- 縁取りをこれ以上太くしたい場合、**先にフォントを太くする**。縁で太らせるのは禁止
- 行間は押し出し分を確保する（`line-height` ≥ 1.15 + 押し出し量。上の行の影が下の行の文字に重なったら不合格）
- 縁取り適用後、キャッチを一文字ずつ音読できるかを最終確認する

#### 発生事例（2026-08-29）

本ルール初版の検証レンダリングで、Webフォントを読み込まないままフォールバックの細いシステムフォントに 10px の白縁 + 押し出しを適用し、キャッチが潰れて可読性が崩壊した状態を「検証済み」として提出。ユーザーから「こんな読みづらいフォントを選ぶデザイナーは首です」と指摘。技法（CSSレシピ）の動作確認とデザインの合格判定は別物であり、フォント読み込み確認を省略した合格判定は許されない。

同日、キャッチのみ Noto Sans JP 900 に修正し、リボン・UIモック・付箋等の他ゾーンを
フォールバックのまま再提出して「その他の文字も全然ダメ」と再指摘を受けた。
**部分修正で合格判定しない。指摘された箇所だけ直して出すのは修正ではなく、
同じ欠陥の再提出である。** チェックは常に全ゾーン一括で行う。

### 縁取り階層（この様式の中核技術）

キャッチコピーは最低3層で構成する:

```
[内] 文字色（単色 or グラデ）
 → [中] 白の縁取り（文字サイズの4-8%幅）
 → [外] 濃色の縁取り or 3D押し出し
 → [最外] ドロップシャドウ
```

```css
/* 基本: 白縁 + 押し出し */
.catch {
  font-weight: 900;
  color: var(--pop-pink-500);
  -webkit-text-stroke: 10px #fff;
  paint-order: stroke fill;   /* 縁が文字の内側を侵食しない */
  text-shadow:
    2px 2px 0 var(--pop-purple-700), 4px 4px 0 var(--pop-purple-700),
    6px 6px 0 var(--pop-purple-700), 8px 8px 0 var(--pop-purple-700),
    10px 10px 0 var(--pop-purple-700),
    16px 16px 32px rgba(31, 18, 53, .35);
}

/* 二重縁取り: 背面に同一テキストを重ねて外縁を作る */
.catch-outline2 { position: relative; }
.catch-outline2::before {
  content: attr(data-text);
  position: absolute; inset: 0; z-index: -1;
  -webkit-text-stroke: 22px var(--pop-purple-700);
}

/* グラデーション文字（縁取りは ::before 側に持たせる） */
.catch-gradient {
  background: linear-gradient(180deg, var(--pop-purple-400), var(--pop-purple-700));
  -webkit-background-clip: text;
  background-clip: text;
  color: transparent;
}
```

### 動きの付け方

- ブロック全体を **-3〜-6° 回転**（`transform: rotate(-4deg)`）
- 行ごと・タグごとに角度と位置を微妙にずらす（階段状オフセット）
- 1文字単位で `translateY` を ±0.05em 互い違いにするとさらに弾む（キャッチのみ。本文には使わない）

### サイズ体系（1080×1350 基準）

| 要素 | サイズ目安 |
|------|-----------|
| メインキャッチ | 120-180px/字（キャンバス高の 9-13%） |
| ロゴロックアップ | 90-140px |
| CTAバースト内 | 48-64px |
| サブコピー・リボン | 28-40px |
| UIモック内テキスト | 16-24px（縮小しても読める下限） |
| バッジ・特徴・注記 | 18-24px |

**最大要素と本文のジャンプ比は 1:4 以上を厳守。** 全要素が中サイズに収束した時点でこの様式は失敗する。

## 4. 装飾ライブラリ（CSS実装レシピ）

装飾は以下から選び、**プロダクトのテーマに合うモチーフに限定**する。全部載せは禁止。

### 4-1. ハーフトーンドット

```css
.halftone {
  background-image: radial-gradient(circle, rgba(255,255,255,.5) 2.5px, transparent 3px);
  background-size: 14px 14px;
  -webkit-mask-image: radial-gradient(circle at 35% 35%, #000 30%, transparent 72%);
  mask-image: radial-gradient(circle at 35% 35%, #000 30%, transparent 72%);
}
```

### 4-2. 放射光線（サンバースト背景）

```css
.sunburst {
  background: repeating-conic-gradient(from 0deg at 22% 12%,
    rgba(255,255,255,.16) 0deg 5deg, transparent 5deg 13deg);
}
```

### 4-3. バーストバッジ（CTA用の爆発形）

```css
/* 正方形3枚を重ねて12角の爆発形にする */
.burst { position: relative; width: 240px; height: 240px; }
.burst i { position: absolute; inset: 0; background: var(--pop-yellow-400); }
.burst i:nth-child(2) { transform: rotate(30deg); }
.burst i:nth-child(3) { transform: rotate(60deg); }
.burst span { position: absolute; inset: 0; display: grid; place-items: center;
  font-weight: 900; font-style: italic; color: var(--pop-ink);
  transform: rotate(-6deg); text-align: center; }
```

### 4-4. 稲妻

```css
.bolt {
  width: 60px; height: 100px; background: var(--pop-pink-400);
  clip-path: polygon(46% 0, 100% 0, 62% 42%, 88% 42%, 22% 100%, 44% 55%, 10% 55%);
  filter: drop-shadow(3px 3px 0 rgba(255,255,255,.9));
}
```

### 4-5. スパークル（✦）

```css
.sparkle {
  width: 24px; height: 24px; background: #fff;
  clip-path: polygon(50% 0, 62% 38%, 100% 50%, 62% 62%, 50% 100%, 38% 62%, 0 50%, 38% 38%);
}
```

### 4-6. ピクセルカーソル（Web/ゲームモチーフ）

```html
<svg viewBox="0 0 16 16" width="48" aria-hidden="true">
  <path d="M3 1 L3 12 L6 9 L8 14 L10.5 13 L8.5 8 L12 8 Z"
        fill="#fff" stroke="#1F1235" stroke-width="1.2"/>
</svg>
```

### 4-7. リボン帯・角度付きタグ

```css
.ribbon {
  display: inline-block; padding: .35em .9em;
  background: linear-gradient(90deg, var(--pop-pink-500), var(--pop-purple-500));
  color: #fff; font-weight: 800;
  transform: skewX(-8deg) rotate(-2deg);
  box-shadow: 6px 6px 0 rgba(31, 18, 53, .18);
}
.ribbon + .ribbon { margin-left: 1.2em; }  /* 2行目を右にずらして階段状に */
```

### 4-8. ステッカー / 付箋

```css
.sticker {
  background: #fff; border-radius: 14px; padding: 18px;
  transform: rotate(-4deg);
  box-shadow: 0 10px 24px rgba(31, 18, 53, .25);
  outline: 2px dashed rgba(124, 58, 237, .35); /* ステッチ風 */
  outline-offset: -8px;
}
```

### 4-9. 吹き出し（ハート型・キャラ台詞）

```css
.bubble-heart {
  background: var(--pop-purple-500); color: #fff;
  padding: 20px 26px; border-radius: 50% 50% 46% 46%;
  position: relative; font-weight: 800;
}
.bubble-heart::after { /* しっぽ */
  content: ""; position: absolute; bottom: -10px; left: 24%;
  border: 12px solid transparent; border-top-color: var(--pop-purple-500);
}
```

### 4-10. グレインオーバーレイ（最前面・全体統一）

```css
.grain {
  position: absolute; inset: 0; pointer-events: none; opacity: .06;
```

## 5. 人物写真のディレクション

写真素材の企画・撮影ブリーフは key-visual-producer が担当。graphic-designer は以下の仕様で依頼する:

| 項目 | 指定 |
|------|------|
| 表情 | 大げさに（ウインク、驚き、満面の笑み）。すまし顔はこの様式に合わない |
| ポーズ | 指差し・手のひら提示など「プロダクトへ視線を送る」ジェスチャー必須 |
| 衣装・小物 | キーカラー同系色（ピンク背景ならピンクの上着）。アクセサリーで情報量を足す |
| ライティング | 背景グラデと同色相のリムライト/色かぶりを入れる（合成感の排除） |
| 背景 | 切り抜き前提の単純背景。高解像度（配置サイズの2倍以上） |
| 配置 | 頭部が上端に近く、体はキャンバス外に切れてよい。手元がUIモックを指す位置関係 |

写真が用意できない段階では、正確なサイズ・位置の**プレースホルダー**（シルエット + 指定表を添付）で組む。

## 6. プロダクト証明（UIモック）

このゾーンが様式の説得力を担う。「賑やかな飾り」の中央に「本物が動いている証拠」を置く。

- 実際のプロダクトUIを簡略化して再現する。**架空のUI・Lorem ipsum は禁止**。実物の画面・実際に読める日本語コピーを流し込む
- 「Step 1 → Step 2」の使い方フローで構成し、番号バッジ（ハート型等モチーフに合わせる）+ 変換矢印でつなぐ
- ブラウザクローム（トラフィックライト・ナビ）/ スマホフレームで「Web で動く / アプリで動く」を無言で伝える
- 会話UIなら実際のやり取り例を最後の成功メッセージ（🎉）まで見せ、体験の完結を描く
- モック内の最小フォント 16px（縮小表示でも読める下限）
- モック内テキストのウェイトは 500 以上（400 は販促ビジュアルの中では貧弱に見える）
- モック自体は白ベース・角丸 20-28px・強めのドロップシャドウで背景から浮かせる

## 7. CTA・ロゴ・バッジ

### CTAクラスタ（右下）

- 黄色バーストバッジ（「今すぐためす！」等の切迫コピー、太字イタリック、-6°回転）
- 直下に白ピルボタン（「ブラウザですぐ遊ぶ →」等の具体的動作コピー + 矢印）
- ピクセルカーソル等の「押せる」メタファーを添える
- アクセント色はこのクラスタとフックタグにのみ使用

### ロゴロックアップ（左下）

- 英字ロゴは3D押し出し（白/シルバー面 + グラデ縁 + 厚い押し出し影）
- 読みがなピル（「チャットゲーム」）を上に、タグライン枠（「PASTE. PLAY. CHAT.」letter-spacing広め）を下に
- ロゴの間に稲妻等のモチーフを1つ挟むと締まる

### カテゴリバッジ（右上）

- 英語大文字 + 半透明白枠ピル × 2-4個。属性の即時伝達（WEB APP / NO INSTALL 等）

## 8. 制作ワークフロー（HTML/CSS KV 標準手順）

1. **要件確認**: 訴求点・ターゲット・媒体とサイズ・素材（写真/ロゴ/マスコット）の有無・締切（`work-style.md` 準拠）
2. **素材棚卸し**: 支給素材の解像度・切り抜き可否を確認。不足分は key-visual-producer へブリーフ発行
3. **ゾーン設計**: 9ゾーン構成をベースにワイヤー（どのゾーンを使い、何を入れるか）を作る
4. **実装**: 固定サイズのアートボード（`width/height` 固定の div）に HTML/CSS で組む。トークン定義 → レイヤー順に構築
5. **検証**: `preview_screenshot` で実寸確認（`preview-before-deploy.md` 準拠。HTMLテキスト確認だけでの合格判定は禁止）
6. **サムネイルテスト**: 幅300px相当に縮小したスクリーンショットで キャッチ / サービス名 / CTA が判読できるか確認
7. **書き出し・圧縮**: スクリーンショットをラスタ化し、用途別に圧縮（`image-production.md` の上限値厳守）
8. **サイズ展開**: 別アスペクト比は再レイアウト。クロップ量産禁止

### アートボードの基本骨格

```html
<div class="artboard"><!-- 1080×1350 固定 -->
  <div class="bg-gradient"></div>
  <div class="sunburst"></div>
  <div class="halftone tl"></div><div class="halftone br"></div>
  <img class="model" src="model.png" alt="">
  <div class="ui-mock">…</div>
  <img class="mascot" src="mascot.png" alt="">
  <h1 class="catch" data-text="貼るだけで">貼るだけで</h1>
  …
  <div class="cta-cluster">…</div>
  <div class="grain"></div>
</div>
```

```css
.artboard { position: relative; width: 1080px; height: 1350px; overflow: hidden; }
.artboard > * { position: absolute; } /* ゾーン設計に基づく絶対配置が基本 */
```

## 9. 品質チェックリスト（完了条件）

| # | 項目 | 基準 |
|---|------|------|
| 1 | サムネイルテスト | 幅300px縮小で キャッチ・サービス名・CTA が判読できる |
| 2 | 全文可読 | 全テキストが実寸で読める。縁取りなしの白文字直置きゼロ |
| 2b | フォント | 指定Webフォント（900級）で描画済み（フォールバック落ちなし）。縁取り幅が比例則の上限内 |
| 2c | コピー | 見出し系（キャッチ・フックタグ・タグライン・バースト）に句読点（、。）が無い |
| 3 | 視線誘導 | Z字フローが成立（人物の視線/指差しが次要素を向く） |
| 4 | 色の統制 | 主役2色相 + アクセント1色に収まっている。アクセントはCTA系のみ |
| 5 | ジャンプ比 | 最大要素:本文 が 1:4 以上 |
| 6 | 装飾の統制 | 顔・文字・UIモック内部に装飾が重なっていない |
| 7 | モチーフ整合 | 装飾モチーフがプロダクトテーマと紐づいている |
| 8 | UIモック | 実UIベース・実コピー・最小16px・成功状態まで描写 |
| 9 | 写真整合 | 人物のライティング色相が背景と合っている |
| 10 | 書き出し | 圧縮済み（Web 300KB以下等、`image-production.md` の上限内） |

1つでも欠けたらボツ。サイズ数を揃えるより1枚の完成品を出す（`image-production.md` 第一原則）。
