# 検証は「壊れる場所」を通っているか

## 第一原則: 手元で通ることは、動く証拠ではない

「ビルド成功」「テスト全通過」は、**その検証が通った経路の話**でしかない。
本番で落ちているのに手元で再現しないとき、真っ先に疑うのは
**自分の検証がそもそも壊れている場所を通っていない**可能性である。

「何度やっても通ります」と報告し続けることは、動いていない現実の否定になる。

## 再現しないときに最初に確認すること

| # | 問い | 確認方法 |
|---|------|---------|
| 1 | 壊れている部品が、手元の環境に存在するか | `ls node_modules/<pkg>` / `grep -r "<エラー文字列>" node_modules/` |
| 2 | 自分の変更が原因か | `git stash` して再現するか見る。戻して再現するか見る |
| 3 | いま見ている出力は、いまのコードのものか | プロセスの起動時刻とポートを確認する |
| 4 | 本番と手元で、実行される処理そのものが違わないか | ビルドログの行数・順序を突き合わせる |

### 1 が最重要

エラー文字列が手元の依存ツリーのどこにも存在しないなら、**その検証は原理的に
再現できない**。何回ビルドしても通る。通ることに意味がない。

```bash
# 本番のエラー文字列を、手元の依存ツリー全体から探す
grep -rl "Unhandled type" node_modules/ | head
# 出てこなければ、その処理は手元に存在しない
```

存在しない場合の手は2つ。**本番のログ全文をもらう**か、**その部品を実物で取ってきて
手元で動かす**（npm レジストリから tarball を落として直接実行する等）。

### 3 を飛ばさない

古いサーバーがポートを掴んだままだと、新しいビルドの確認をしているつもりで
古い出力を見ることになる。`npm run start` が `EADDRINUSE` で落ちても、
バックグラウンド起動では気づかない。

```bash
ps -eo pid,etime,cmd | grep next-server   # 起動からの経過時間を見る
```

## 報告の仕方

「動きます」と書かない。**どの環境で、何を通して、何を通していないか**を書く。

```
Bad:  31項目すべて通過しました。問題ありません。
Good: このコンテナで31項目通過。ただし @vercel/static-config は
      node_modules に存在しないため、本番で落ちている経路は通っていない。
```

## 直したら、その経路を検証に足す

同じ壊れ方をしたら落ちるようにする。検証項目が増えないなら、
その修正は次に再発する。

## 発生事例（2026-08-30）

### 壊れている部品が手元に無かった

Vercel のビルドが `Unhandled type: "ColonToken"` で落ち続けた。手元では
新規clone + `npm ci` + `next build`（Turbopack / webpack 両方）が通り、
`tsc` も `eslint` も通った。「コードに問題はない」と報告した。

原因は Vercel の `@vercel/static-config` が `middleware.ts` の
`export const config` を ts-morph で読む処理で、`getChildren()` の戻り値を
位置決め打ちで分解していた。JSDoc コメントがあると添字が1つずれて例外になる。

このパッケージは **リポジトリの node_modules に存在しない**（Vercel のビルダーが
動的に取得する）。手元でどれだけビルドしても、この経路は一度も通らない。
npm から実物の tarball を取得して食わせ、エラー文字列を1バイト違わず再現して
初めて特定できた。

ユーザーからは「あなたは現実を見ませんが」と言われた。そのとおりだった。

### 自分の変更が原因かを確認せず、環境のせいにしかけた

GA4 を入れた後、言語切替のプリフェッチが一部ロケールで404になった。
`git stash` して3回、戻して3回走らせ、自分の変更が原因だと確定させた。
さらに外部スクリプトとインラインスクリプトを個別に外して、インライン側が
引き金だと絞り込んだ。この手順を踏まなければ「たまにある404」で流していた。

### 古いサーバーの出力を見ていた

アイコンの link タグが出ないと判断しかけたが、7分前に起動した古いサーバーが
ポート3000を掴んでおり、新しいビルドを見ていなかった。
