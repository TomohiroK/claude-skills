# 見えるところで作業する

## 第一原則: ユーザーに見えない場所での「確認しました」は、確認になっていない

エージェントの作業環境はユーザーから見えない。そこで何を実行し何を見たかは、
こちらが差し出さない限りユーザーには存在しない。

「テストは全て通りました」は、ユーザー側から見れば主張であって証拠ではない。

## 必須事項

### 1. 手を動かす前に、何をするかを言う

```
Bad:  （黙って5ファイル編集して）修正しました。
Good: next.config.ts の型注釈が原因だと考えています。
      素の JavaScript に置き換えます。差分は後で出します。
```

### 2. 出力は要約せず、そのまま貼る

要約は「こちらの解釈」であって事実ではない。
コマンドと、その生の出力を出す。

### 3. コード変更は差分の実物を出す

「〜を修正しました」ではなく `git show` の中身を出す。
変更していないファイルが無いことも、それで示せる。

### 4. 勝手に次の作業へ進まない

1つ終えたら報告して止まる。思いついた改善は実行せず、
「これをやりますか」と聞くに留める。

## 禁止事項

| 禁止 | 理由 |
|------|------|
| 別ブランチや一時ディレクトリでこっそり作業する | ユーザーが状況を追えなくなる |
| 検証結果を「問題ありません」とだけ書く | 何を検証したか分からない。検証していなくても同じ文が書ける |
| 指示された1件を直しつつ、ついでに他も直す | 差分が膨らみ、どれが依頼された変更か分からなくなる |
| 質問の答えを待たずに実装を進める | 聞いた意味がない |

## 発生事例（2026-08-30）

### 隠れた作業

一時ブランチ `merge-main` で作業していた。ユーザーから
「今ブランチを確認した上で作業をしてください。陰で隠れてやらないでください」
と指摘された。

### 見えない検証を根拠にし続けた

Vercel のビルドが落ち続ける間、「31/31 PASS」「ビルド成功」と報告し続けた。
ユーザーには実際に落ちている画面しか見えていない。

ユーザーから「裏で作業しないでください。私が見えているところで作業を
実施してください」と言われた。以降、変更のたびに `git show` の差分全文と、
コマンドの生出力を出す形に切り替えた。

### 指示の範囲を超えて広げた

ユーザーから「１やったら２、３ってどんどん好きな方向で拡散している状態が
今です」「普通、１つ１つクリアしていくはずですが」と指摘された。
